# TicketRush — 티켓팅 실전 연습 시뮬레이터

실전은 단 한 번입니다. 연습은 몇 번이든.

국내 예매처의 실제 예매 흐름(대기열 · 보안문자 · 좌석 선점 경쟁 · 서버 지연)을 재현하고,
끝나면 반응속도와 클릭 습관을 분석해 무엇을 고쳐야 하는지 알려주는 연습 도구입니다.

**빌드 도구나 서버가 필요 없습니다.** `index.html`을 브라우저로 열면 바로 실행됩니다.

## 실행 방법

`index.html` 더블클릭, 또는

```bash
start "" index.html
```

## 모드

우측 상단 **☰** 메뉴에서 고릅니다.

| 모드 | 내용 |
|---|---|
| **전체 연습** | 오픈 대기부터 결제까지 한 판을 통째로 |
| **보안문자 집중 연습** | 보안문자 구간만 5~20문제 연속 반복 |

전체 연습에서는 보안문자가 한 판에 한 번만 나옵니다. 그 구간만 따로 반복하고 싶을 때
홈 화면의 **`보안문자 연습 →`** 버튼으로 들어갑니다. 보안문자 생성·렌더링 코드
(`js/captcha.js`)를 양쪽이 공유하므로 집중 연습에서 익힌 감각이 실전 흐름과 어긋나지 않습니다.

## 연습 흐름

```
오픈 대기 → 대기열(대기번호) → 보안문자 → 날짜/회차 → 구역 → 좌석(포도알) → 결제 → 분석
```

1. **오픈 대기** — 버튼이 활성화되는 순간의 반응속도를 측정합니다. 미리 누르면 무효 처리됩니다.
2. **대기열** — 반응속도가 대기번호를 결정합니다. 새로고침하면 순번이 뒤로 밀립니다.
3. **보안문자** — 실제 예매처처럼 좌석을 보기 전에 나옵니다. 여기서 흘린 시간만큼 좌석이 팔립니다.
4. **날짜/회차** — 회차마다 경쟁률이 다릅니다. 주말·막공은 좌석이 더 빨리 사라집니다.
5. **구역** — 공연장 좌석배치도에서 구역을 고릅니다. 색이 옅을수록 많이 팔린 구역입니다.
6. **좌석** — 포도알을 선택합니다. 좋은 자리일수록 남에게 뺏길 확률이 높습니다.
7. **분석** — 7개 지표를 벤치마크와 비교하고, 개선 방법을 문장으로 제시합니다.

## 측정 지표

| 지표 | 설명 |
|---|---|
| 반응속도 | 오픈 순간부터 예매 버튼 클릭까지. 결과의 절반 이상을 결정합니다. |
| 회차 선택 소요시간 | 미리 정해두지 않으면 이 구간에서 좌석이 사라집니다. |
| 좌석 선택 소요시간 | 좌석 화면 진입부터 첫 좌석 확보까지. |
| 클릭 정확도 | 전체 클릭 중 유효한 대상을 누른 비율. |
| 마우스 경로 효율 | 최단거리 대비 실제 커서 이동거리. |
| 연속 클릭 속도 | 가장 빠른 1초 구간의 클릭 수. |
| 침착도 | 불필요한 새로고침·연타·매진 좌석 클릭이 적을수록 높습니다. |

## 공연장

홈 화면에서 6개 공연장 중 하나를 고릅니다. 공연장마다 좌석배치도 구조가 다릅니다.

| 공연장 | 실루엣 |
|---|---|
| 예술의전당 콘서트홀 | **부채꼴** — 플로어 없이 정면으로만. 뒤 발코니 + 측면 박스석 |
| 잠실실내체육관 | **타원** — 사각 플로어를 납작하게 눌린 2개 층이 감쌈 |
| 인스파이어 아레나 | **말발굽** — 100번대를 여덟 블록으로 잘게 쪼갠 신축 아레나 |
| KSPO DOME (체조경기장) | **원형** — 객석이 무대 옆을 지나 뒤까지 300도 감김 |
| 고척스카이돔 | **야구장** — 파울라인 따라 기울어진 내야 + 깊고 완만한 외야 곡선 |
| 서울월드컵경기장 | **사각** — 감싸지 않고 마주보는 야외 스탠드 |

배치도는 `사각 블록` · `도넛 조각(타원 지원)` · `다각형` 세 가지 도형을 조합해 그립니다
(`js/data.js`의 각 구역 `shape` 필드). 공연장마다 층 수와 좌석 등급 구성도 다릅니다.

> 실제 공연장의 구조(플로어 배치, 층 수, 감싸는 각도, 스탠드 형태)를 참고해 비율을 맞춘
> **재구성**입니다. 공식 좌석배치도를 그대로 옮긴 것이 아니므로 구역 번호와 좌석 수는 실제와 다릅니다.

## 난이도

| 난이도 | 동시접속 | 좌석 | 매진까지 |
|---|---|---|---|
| 연습 | 24,000명 | 3,600석 | 약 9분 |
| 실전 | 95,000명 | 2,600석 | 약 3분 |
| 피켓팅 | 320,000명 | 1,700석 | 약 78초 |
| 지옥 | 850,000명 | 850석 | 약 34초 |

좌석 소진 속도는 여기에 **대기번호**(좌석당 앞사람 수)와 **회차 인기도**, **목표 좌석**이
곱해집니다. 목표를 좁히면 그 조건에 맞는 좌석이 먼저 사라집니다.

## 랭킹

결과 화면에 두 종류의 랭킹이 뜹니다.

- **기록 랭킹** — 이 브라우저에 실제로 저장된 기록만 비교합니다. 가상의 경쟁자를 만들지
  않습니다. 홈 화면에서 플레이어 이름을 바꿔가며 같은 기기에서 여러 명이 겨룰 수 있습니다.
- **온라인 랭킹** — 다른 사람·다른 기기와 진짜로 비교하려면 점수를 모아둘 서버가 필요합니다.
  무료 **Supabase** 프로젝트를 하나 만들어 연결하면 됩니다. 순서와 실행할 SQL은 결과 화면의
  온라인 랭킹 박스에 그대로 표시됩니다. 접속 정보는 코드에 넣지 않고 그 화면에서 입력받아
  브라우저의 `localStorage`에만 저장합니다.
  - 테이블 1개(`scores`)만 씁니다 — 방·메시지가 있던 예전 커뮤니티 채팅보다 훨씬 단순합니다.
  - 반응속도는 난이도와 거의 무관한 개인 반사신경 지표라 온라인 랭킹도 난이도 구분 없이
    전체를 한 줄로 세웁니다. 난이도는 표시용으로만 같이 저장됩니다.
  - **`anon public`(또는 Publishable) 키만 사용합니다.** `service_role`(Secret) 키는
    전체 권한을 가지므로 절대 넣으면 안 됩니다.

## 구조

```
index.html          화면 골격
css/style.css       전체 스타일
js/core.js          네임스페이스 · 시드 난수 · 유틸 · 이벤트버스
js/data.js          공연 · 공연장 배치도 기하 · 난이도 · 벤치마크
js/telemetry.js     클릭 · 마우스 · 구간 시간 계측
js/sim.js           서버 부하 · 응답 지연 · 대기열 엔진
js/seats.js         좌석 배치 생성 · 경쟁자 좌석 소진 엔진
js/rank.js          실제 기록 기반 랭킹 (이 브라우저 안)
js/leaderboard.js   온라인 랭킹 (Supabase REST, 다른 기기와 비교)
js/captcha.js       보안문자 생성 · 렌더링 (두 모드 공유)
js/drill.js         보안문자 집중 연습
js/analysis.js      지표 환산 · 피드백 생성
js/ui.js            렌더링 · 좌석배치도 SVG · 캔버스 차트
js/app.js           진행 상태기계
```

의존성 없는 순수 HTML/CSS/JavaScript입니다.

## 안내

개인 연습용 시뮬레이터입니다. 실제 예매 사이트와 무관하며 어떤 예매처와도 통신하지 않습니다.
자동화·매크로 기능은 제공하지 않습니다.
